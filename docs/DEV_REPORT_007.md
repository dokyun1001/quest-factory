## 6. 성능 (TEST E, 헤드리스 소프트웨어 렌더링 — 실제 PC 아님)

게임 처리 시간(시뮬레이션 + 갱신)과, GPU가 없는 환경의 FPS를 따로 적습니다. 이 환경은 빈 월드에서도 FPS가 약 35에 묶여 있습니다.

| 상황 | 게임 처리(ms/프레임) | FPS(소프트웨어) |
|---|---|---|
| 빈 성능 월드 | 0.21 | 35.5 |
| 컨베이어 1,000 / 5,000 / 9,900 — 화면 밖 | 0.20 / 0.47 / 0.80 | 36 / 35 / 35 |
| 컨베이어 9,900 — 화면에 수천 개(2배 확대) | 1.58 | **15.5** (그리기 비용) |

| 모험가 500 + 주민 1,000 + 컨베이어 9,900 + 몬스터 64 | 3.64 | 29.6 |

- 저장·불러오기(모험가 521, 컨베이어 9,900, 시설 331, 주민 1,500): 직렬화 23 ms, 크기 2.0 MB, 복원 35 ms. 복원 후 개수 전부 일치.

## 7. 발견한 문제와 개선 제안

1. **경제 순환 정지**(가장 중요): 모험가 쪽에 돈이 쌓이는 문제 → 돈을 쓰게 하는 장치 제안(숙박·식비, 장비 수리, 교육비, 매입 수수료)과 길드 외부 수입원(대형 계약, 지역 의뢰 보상) 검토가 필요합니다. 시작 자금 400G 대비 모집비 40G도 재검토가 필요합니다.
2. **서식지 수용량**: 모험가 수에 비해 몬스터가 부족 → 서식지 증설, 의뢰 수량을 서식지 규모에 맞추기, 실패 대신 연장.
3. **장수 종족의 장기 우세**: 혼혈 자녀 종족 규칙, 종족별 출산 가능 기간, 은퇴 기준을 활동 연수로 하는 안 등을 기획 확정 요청합니다.
4. **처리량 균형**: 기초 벨트 0.625개/초, 채굴 12초/개, 용광로 20초/개라 채굴기 1대가 용광로 1.7대를 먹입니다. 초반 템포(20~30분 목표)에 맞는지 실제 플레이 확인이 필요합니다.
5. **S방향 용광로**: 출구와 광석 입구가 붙어 있어 배치가 어렵습니다(아트 검토 필요).
6. 렌더링: 성능 실험실 수준의 대량 화면에서는 청크 단위 정적 캐시를 제안합니다.
