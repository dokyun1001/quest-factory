## 5. 시험 결과 및 환경

**환경:** Claude Code 클라우드 컨테이너(Linux, 4 vCPU), Node 22.23, 헤드리스 Chromium 158 (Playwright), **GPU 없음 — 소프트웨어 렌더링(SwiftShader)**, 화면 1280×760. **실제 사용자 PC 결과가 아닙니다.** 사용자 PC에서 확인이 필요합니다.

### 물류 단위 시험 (`node web/test/sim.test.mjs`) — 전부 통과
- 직선(W→E), 코너 WS·NW·EN 모양 판정 / 테스트 배치에서 12방향 조합 전부 사용
- 긴 직선 20타일: 40초에 26개 전달 · 수직 10타일(N→S, S→N): 각 33개
- 지그재그(동쪽·서쪽 방향, 코너 8종): 전달 확인
- 막다른 끝: 맨 앞 물건이 벨트 안에서 대기, 줄 선 물건 최소 간격 0.600타일 유지
- 닫힌 저장소로 막힘 → 열면 10초에 20개 회복
- 채굴기→컨베이어→제련기→컨베이어→저장소: 철괴 14개 / 금 채굴기→코너 경로→저장소: 확인

### 성능 (헤드리스 소프트웨어 렌더링 수치 — 참고용)
게임 자체 처리 시간(시뮬레이션 + 갱신)은 모든 경우 **프레임당 0.3ms 미만**이었습니다. FPS는 이 환경의 소프트웨어 렌더링 한계(아무것도 없는 상태에서도 약 37fps)에 묶여 있으므로 실제 PC 성능을 나타내지 않습니다.

| 상황 | 물류 시뮬(ms/프레임) | 게임 갱신(ms) | FPS(소프트웨어) | 텍스처 |

### 이전 성능 문제 재발 방지 (설계)
- **아틀라스 1장 = GPU 텍스처 1개**를 모든 컨베이어·아이템·시설이 공유 (이전의 아틀라스 복제 문제 원천 차단). 아틀라스 256×1024, 17KB.
- 물류는 **고정 60Hz 단계**로 계산하고 렌더링과 분리. 프레임이 늦어도 한 번에 최대 8단계만 따라잡음(멈춤 방지).
- 컨베이어는 16×16타일 묶음(chunk) Blitter로 그리고, 화면 밖 묶음은 숨기고 애니메이션 갱신도 생략. **생산·운송은 화면 밖에서도 계속**.
- 아이템은 객체를 재사용(시뮬레이션 객체 풀 + 화면 표시 Bob 풀). 화면 안 아이템만 그림.
- 캐릭터 외형은 **외형이 바뀔 때만 합성**하고, 같은 외형은 텍스처 1개 공유(참조 계산 후 해제). 100명에 외형 텍스처 83개.
- UI는 DOM으로 0.12초마다만 갱신.
- 지형은 캔버스 1장에 한 번 그림(발견 시에만 다시 그림). 테스트 배치 지형이 1792×1280이라 텍스처 메모리 대부분(약 9.2MB)을 차지합니다 — 정식 지형 아트 적용 시 타일맵 방식으로 바꿀 예정.

## 7. 아트 메타데이터와 기능의 차이 (확정하지 않고 보고)
- 시설 설치 2×2, 지면 기준점 (16,30), 포트 위치는 메타데이터 후보값을 그대로 사용했습니다. 충돌은 2×2 전체를 막는 시험값입니다.
- 채굴기·제련기는 회전 아트가 없어 **회전 불가**(출력은 항상 동쪽 아래). 실제 배치 자유도에 영향이 있습니다.
- 제련기는 철괴 아트만 있어 철광석만 처리합니다(금광석은 받지 않아 벨트에서 대기).
- 코너에서 아이템은 "입력 변 중앙 → 타일 중심 → 출력 변 중앙" 경로를 따릅니다(아트의 운송부 중심과 일치). 코너 애니메이션 근사 표현의 시각 품질은 사용자 확인이 필요합니다.
- 속도 1.5타일/초, 간격 0.6타일, 채굴 2초, 제련 3초, 공급 1초, 발견 반경 6타일은 모두 **시험값**입니다.
